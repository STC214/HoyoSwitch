# 星铁登录状态点位与项目进度

更新：2026-11-19，时间均为北京时间（UTC+8）。实测对象：星穹铁道大陆客户端 4.7.0（版本代码 122），包名 `com.miHoYo.hkrpg`，Android 主用户 0。本报告的真机结论仅适用于已测设备和版本；原神、绝区零尚未完成同类验证。

## 1. 结论

- **最可靠的本地状态点位**：Porte 生产环境偏好里的 `login_status`。它是客户端当前会话共用的布尔值，不是每个已保存账号各有一份。A、B 均已登录时读到 `true`，用户清除登录状态后读到 `false`，重开仍是 `false`。
- **同名不等义**：另一份 SDK 偏好也有 `login_status`。在已实测的未登录状态下，它仍是 `true`，即使文件更新也没有跟随 Porte 的标志变化。
- **本地状态不等于认证结果**：单个布尔值不证明服务端会话有效，也不表示用户已进入游戏角色。没有实际修改这个标志，未验证改写后的行为。
- **没有找到独立的「登录中」持久化标志**。静态代码有开始、成功、失败和登出事件，但事件不等于持续状态；不把未找到字段当成字段不存在的证明。

## 2. 文件与数据库点位

下表路径均相对于 `/data/user/0/com.miHoYo.hkrpg/`。

| 位置 | 观察项 | 可用于 | 不能单独用于 |
| --- | --- | --- | --- |
| `shared_prefs/porte_sdk_account_PRODUCT.xml` | `login_status`、文件修改时间 | 区分这次实验中的本地已登录／未登录 | 判定账号身份、服务端认证、登录中 |
| `shared_prefs/mihoyo_sdk_preference.xml` | 同名 `login_status`、文件修改时间 | 辅助对比不同模块更新次序 | 判定已登录；实测退登后仍为 `true` |
| `databases/h5log_db_porte_login` | 只检查大小和文件修改时间；最近检查时 20,480 字节 | 关联操作时间线 | 单凭更新判断登录成功；未登录重开时也会更新 |
| `databases/h5log_db_porte_login-journal` | 最近检查时 512 字节，最后修改于 11 月 18 日 23:18:14 | 识别日志数据库伴随文件 | 表示近期登录或登出事件 |
| `databases/h5log_db_porte_login-wal`、`databases/h5log_db_porte_login-shm` | 11:57:56 未发现 | 记录该次采样的文件布局 | 证明其他时刻从未生成 |
| `shared_prefs/h5log_sp_porte_login.xml` | 11:57:56 未发现 | 排除本次可用的辅助点位 | 推断日志功能未运行 |
| `databases/PORTE_ACCOUNT_PRODUCT.db` 中的 `porte_account_table` | 已核对的表结构没有独立登录状态列；`timestamp` 属于账号记录 | 区分「保存过账号」和「当前已登录」两个概念 | 把有记录、记录条数或记录时间当成认证成功 |
| `shared_prefs/combo_widget.xml` | 静态证据表明是桌面组件下游缓存 | 解释为什么正常登录后可能出现关联更新 | 当作游戏的登录入口或权威状态 |

在 Porte 状态 XML 中按 `time`、`date`、`stamp` 命名筛选，未发现匹配的时间字段。这不等于排查了所有潜在编码；目前只确认可见的**整个文件修改时间**，不是布尔值专属的变更时间。采样时刻、文件修改时刻、用户确认时刻应分别记录。

## 3. 真机对比时间线

各行的登录状态由用户手动确认，表格只保留布尔值和修改时间。没有抓取登录凭据或读取日志库内容。

| 采样时间 | 用户确认状态 | Porte 值 / 修改时间 | SDK 同名值 / 修改时间 | H5 日志库修改时间 |
| --- | --- | --- | --- | --- |
| 11:29（基线） | B 已登录 | `true` / 11:20:50 | `true` / 10:42:40 | 11:21:00 |
| 11:48:37 | B → A 后，A 已登录 | `true` / 11:47:51 | `true` / 10:42:40 | 11:47:52 |
| 11:50:43 | 用户已移除所有账号的登录状态 | `false` / 11:49:31 | `true` / 11:49:59 | 11:50:19 |
| 11:52:02 | 关闭并手动重开后仍未登录 | `false` / 11:49:31 | `true` / 11:51:32 | 11:51:42 |

可据此排除两个误判：从 B 切到 A 后布尔值不变，并不代表没切换；未登录时 H5 日志库和 SDK 偏好也会更新，并不代表登录成功。此前另做过官方界面 A ↔ B 双向冷启动测试，重开后都保留了目标账号；那不是第三方文件恢复测试。

## 4. 静态证据如何解读

- `PorteAccountManager.getLoginStatus` 和 `getLoggedAccount` 的静态结果表明，本地标志为 `false` 时 SDK 不返回已登录账号。`true` 只是该检查的一个条件。详见[第一轮 APK 静态分析](星铁账号切换调用链-20261119.md)。
- SDK 区分登录开始、登录成功／失败、登出成功；验证环节通过与整个登录流程成功是两类结果。参考证据前缀：`ev_08d0d0d7`、`ev_6a7a201e`、`ev_9c696b67`。
- H5 遥测相关逻辑有异步写入、达到容量阈值后的清理和上传成功后的删除路径。日志库没有可直接当作当前状态的稳定标志，尚未证明各登录阶段都写进该库。参考证据前缀：`ev_70faa2b7`、`ev_6dee3e81`、`ev_6b24ecf6`、`ev_d38350fc`。

## 5. 实现进度与未完成项

- **自有测试 App**：已安装并使用项目根目录的 `0i.png`。A/B 按钮和「切换后自动打开」开关已加入。自动验收在用户要求接手前验证了 A → B 自动重开并更换进程；新版按钮的关闭开关分支没有跑完自动验收。旧版 ADB 原型的回退验收见[原型说明](../prototype.md)。两种测试都只针对自有 App。
- **真实游戏**：只完成官方界面行为观察、静态分析和布尔值／文件元数据对比。没有实现写入登录标志，也没有将真实游戏登录状态恢复接入测试 App。非 Root 验证中，星铁发行版的 `run-as` 返回 `package not debuggable`；未验证到供第三方 App 使用的恢复入口。
- **备份工具箱**：原有工具是独立项目。此前已确认其 `user` / `user_de` 归档范围，不等于只有账号文件，也未将其全部功能移植到本项目。原始备份仍仅保留在 Git 忽略的 `account-snapshots/`，本报告不附原始数据。
- **签名**：测试 APK 使用本地测试密钥；正式包名、发布证书和密钥管理尚未交付。
- **建议的下一次只读对比**：如用户本来就要重新登录，只记录发起前、等待结果、用户手动确认后三次的布尔值与修改时间。如果过渡太快或两处读数冲突，则记录「未采到／未知」。无需为补样强行退出，也不截图核对账号身份。
