### 3.1 当前账号判定：不能取 token 的第一个 key

登录过两个账号后，`porte_sdk_token_PRODUCT.xml` 里会**同时存在两个 key**：

```
<string name="0a0ycvi51n_mhy_mhy_porte_cookie_token_key">…</string>   <!-- A -->
<string name="0032ruoysk_mhy_mhy_porte_cookie_token_key">…</string>   <!-- B -->
```

所以「第一个 key」不代表当前账号。可行判据是账号库：`porte_account_table` 每行形如
`<mid><aid><type><13 位时间戳><加密 blob>`，**timestamp 最大的那一行就是当前账号**。
App 里用正则 `([0-9a-z_]+_mhy)(\d+)(\d{13})` 扫描 DB 字节，取最大时间戳对应的 mid；
拿不到时再退回 token key 首项。

## 6. SDK 的账号数量上限（实测字节码）

结论：**没有 3 个账号的限制**。SDK 默认上限 10，两款游戏的自定义模块都把它提高到 **50**；
超过上限时删除 `timestamp` 最旧的一条。

证据（从 `base.apk` 提取 `classes*.dex` 后用 androguard 反汇编）：

| 位置 | 字节码 | 含义 |
| --- | --- | --- |
| `com.mihoyo.platform.account.sdk.PorteAccountManager.<clinit>` | `const/16 v0, 10` → `sput ... accountNumberLimit` | SDK 默认上限 10 |
| `com.porte.ui.custom.PorteCustomModule.init()`（原神与星铁都有） | `const/16 v1, 50` → `invoke ... setAccountNumberLimit(I)` | 游戏把上限改成 50 |
| `PorteAccountManager.saveAccount` | `invoke isNumberLimit(mid, loginType)`；命中则 `invoke AccountDao.deleteOldestOne()` | 新增账号前检查上限，超限先删最旧 |
| `PorteAccountManager.isNumberLimit` | `accountExist(mid, loginType)` 为真 → 返回 false；否则比较 `currentNumbers()` 与 `accountNumberLimit` | 已存在的账号不占新名额、不触发删除 |
| `AccountDao.currentNumbers()` | `query("porte_account_table", ...)` 计数 | 统计整张表，不区分登录方式 |
| `AccountDao.deleteOldestOne()` | `query ... order by timestamp asc`，删第一条 | 淘汰最久未使用的账号 |

补充：

- `porte_account_table` 主键是 `mid`，没有触发器或行数约束，上限完全由上述 Java 逻辑控制。
- 未发现独立于账号表的 token 数量上限；token 只是按 `<mid>_mhy_porte_cookie_token_key`
  存进 `porte_sdk_token_PRODUCT.xml`。
- 实际影响：账号被 SDK 淘汰后，即使本地还留有该账号的快照，也无法直接切换成功（需要重新登录），
  所以 App 端最多支持到 50 个账号/游戏。
- 「3 个」更可能来自登录界面的列表展示（可见区域只放几个账号），不是存储上限。
