# 绝区零账号状态点位与验证记录（2026-11-19）

- 游戏：绝区零 `com.miHoYo.Nap` 3.3.0（versionCode 438），入口
  `com.miHoYo.Nap/com.mihoyo.combosdk.ComboSDKActivity`（与星铁相同的 ComboSDK 壳）。
- 设备：Xiaomi 23117RK66C（fuxi），Android 16，Root（KernelSU）。

## 1. 当前进度：只做了「空状态」基准，切换未验证

登录前数据目录非常干净（3 个文件）：

```
shared_prefs/com.miHoYo.Nap.v2.playerprefs.xml
databases/COMBO_REPORT.db
databases/COMBO_REPORT.db-journal
```

没有 `porte_sdk_account_PRODUCT.xml`、没有 token prefs、没有 `PORTE_ACCOUNT_PRODUCT.db`、
没有 `combo_widget.xml`——说明这台机器上的绝区零从未登录过。

## 2. App 端的临时状态

`GameProfile.ZZZ` 已登记为「可拍摄、切换待验证」：

- 拍摄清单（11 个文件，按星铁 + 原神的并集先行登记）：
  `porte_sdk_account_PRODUCT.xml`、`porte_sdk_token_PRODUCT.xml`、`mihoyo_sdk_preference.xml`、
  `combo_widget.xml`、`mhy_plat_porte_crypto.xml`、`mdk_passport_sp.xml`、
  `com.miHoYo.Nap.v2.playerprefs.xml`、`PORTE_ACCOUNT_PRODUCT.db`(+journal)、
  `mihoyo_account`(+journal)
- 账号识别：暂按星铁模型（`porte_sdk_account_PRODUCT.xml` 的 `login_status` +
  `combo_widget.xml` 的 `account.mid`），登录后按实际文件校正
- 切换集合：暂填星铁的 4 个文件，但 `switchVerified = false`，卡片上的「切换到此账号」禁用，
  只允许拍摄/更新

## 3. 登录后的结构（2026-11-19 21:54，账号 A）

登录后数据目录从 3 个文件涨到 73 个，其中与账号相关的是：

```
shared_prefs/porte_sdk_account_PRODUCT.xml   login_status=true
shared_prefs/porte_sdk_token_PRODUCT.xml     <0a0ycvi51n_mhy_mhy_porte_cookie_token_key>
databases/PORTE_ACCOUNT_PRODUCT.db           porte_account_table 一行
databases/mihoyo_account
shared_prefs/mihoyo_sdk_preference.xml
```

**没有 `combo_widget.xml`** —— 绝区零与原神同构（token prefs + 账号库），不是星铁的 combo_widget 模型。
`porte_account_table` 行：

```
mid=0a0ycvi51n_mhy  aid=346975607  type=2  timestamp=1795096081742
```

因此 `GameProfile.ZZZ` 改成与原神一致的配置：`identityPrefs=null`、
`tokenPrefs=porte_sdk_token_PRODUCT.xml`、`accountDb=PORTE_ACCOUNT_PRODUCT.db`，
账号识别用「账号库 timestamp 最新的一行」。

| 方向 | 操作 | 游戏内 UID |

| B → A | App 停游戏 → 写 3 个文件 → 校验 → 拉起 | **17444270** |

两个 UID 不同，且切换后游戏能正常进入登录/资源流程，说明这 3 个切换文件足够：


切换后首次进入会弹「资源下载：缺少相关资源」，属于账号内容差异提示，与切换机制无关。

`GameProfile.ZZZ` 已按此配置并打开 `switchVerified`；点击切换会先自动停游戏。
