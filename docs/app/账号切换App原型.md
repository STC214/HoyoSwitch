# 账号切换 App 原型

更新：2026-11-19。包名 `dev.hoyoswitch.app`（临时），版本 0.1，仅面向星铁 4.7.0 的已测设备。这是可运行的最小原型，不是交付版本。

## 1. 已实现

| 功能 | 说明 |
| --- | --- |
| Root 检测 | 依次探测 `su`、`/system/bin/su` 等候选路径，验证返回 `uid=0`；把失败原因显示在状态行 |
| 星铁识别 | 包名、版本（`dumpsys package`）与进程状态（`pidof`）；游戏运行中禁用拍摄 |
| 拍摄快照 | 读取 6 个偏好文件与 2 套数据库（含 `-journal`）共 10 个目标，逐文件记录大小、SHA-256、属主、权限、SELinux 上下文，副本存入 App 私有目录 |
| 当前账号识别 | 读 Porte 的 `login_status` 判断是否登录，再用 `combo_widget.account` 的账号标识与各快照比对；状态行显示「当前账号：<快照名>」，对应卡片标注「当前登录」 |
| 切换前确认 | 点切换后先停游戏、读取当前账号，再弹出「当前账号 → 目标账号」确认框；无法识别时明确写出「未登录」「不在任何快照中」或读取失败原因 |
| 卡片更新快照 | 每张卡片带「更新此快照」：仅当当前登录的就是该卡片账号时才允许，避免把别的账号覆盖进去 |
| 卡片菜单 | 每张卡片的「⋯」提供重命名、删除快照、历史版本；历史版本可回滚，回滚前先把当前版本归档 |
| 悬浮按钮 | 常驻悬浮的「更新快照」按钮（需悬浮窗权限），可拖动；用于切换并加载完成后，在游戏里直接刷新当前账号的快照 |
| 按游戏分栏 | 顶部三个分栏（原神／星穹铁道／绝区零），各自独立的快照列表与状态；快照按游戏包名分目录存放，不会混在一起 |
| 回滚自检 | 调试构建可用 `am start … --ez selftest true` 触发：注入一次写后校验失败，要求设备自动回到切换前状态并输出 PASS／FAIL |
| 卡片操作自检 | 调试构建可用 `--es selftest cardops` 触发：验证重命名、删除、历史版本计数并输出 `CARDOPS PASS/FAIL` |
| 账号卡片 | 每个账号一张卡（按账号标识去重），显示名称、时间与「存在/总数」文件数 |
| 切换账号 | 只写已验证的 4 个文件；写前自动拍安全快照，逐文件读回校验，失败自动回滚；可选自动启动游戏 |
| 启动游戏 | `am start -W` 启动星铁 |

截图与命令记录见下文第 4 节。

## 2. 实现要点

- **命名空间**：App 进程处在 per-app mount namespace 中，直接 `su -c cat /data/user/0/<游戏包>` 会返回 `No such file or directory`。因此所有 root 命令都包一层 `nsenter -t 1 -m -- sh -c '<命令>'`，进入 init 的挂载命名空间后再访问。这是本原型能读写游戏数据的必要条件。
- **写入方式**：把字节写到 `su -c "cat > 目标文件"` 的标准输入，保留 inode，因此属主、权限与 SELinux 上下文不变。
- **安全快照**：每次切换前先把当前状态原地写回当前账号已有的卡片（旧内容进历史）；只有该账号还没有卡片时才新建一张「切换前自动备份」。任一文件校验失败就按这份安全快照回滚，并在界面日志里说明。若要切换的目标正是当前已登录账号，直接提示「当前已经是这个账号，无需切换」，不写任何文件。
- **只写 4 个文件**：`porte_sdk_token_PRODUCT.xml`、`mihoyo_sdk_preference.xml`、`combo_widget.xml`、`PORTE_ACCOUNT_PRODUCT.db`（依据[账号状态快照](../tools/账号状态快照.md) 5.2／5.4 的实测结论）。
- **当前账号识别**：不能用文件哈希——客户端每次启动都会重写令牌、SDK 偏好与数据库 `timestamp`，启动后哈希必然与快照不同。实际做法是读 `login_status` 判断是否登录，取 `combo_widget.account` 里的 `mid` 与各快照的同一字段比对；界面只显示快照名称，不显示账号标识。
- **更新快照语义**：拍摄与更新都直接读取当前状态，**不需要停止游戏**；按当前账号匹配卡片后原地重写该卡片的 10 个文件，卡片名称与目录不变。不做自动更新——是否更新由用户手动决定。手动「拍摄快照」同理：账号已有卡片就原地更新，没有才新建。只有切换账号会先停止游戏。
- **运行中拍摄的一致性**：游戏运行时会持续改写令牌与数据库，`captureOne` 对每个文件读两次并要求内容一致（最多 3 轮、间隔 150ms），避免把写了一半的文件归档；仍不稳定时记录警告并用最后一次读取，保证拍摄不会因游戏在跑而失败。`forceStop()` 发出 `am force-stop` 后会轮询 `pidof`（最多 4 秒）确认进程真正退出，避免紧接着的切换校验误判「游戏正在运行」。
- **只保留一张卡的实现**：`captureAccount` / `snapshotCurrentAccount` 先按账号标识找现有卡，命中就 `updateSnapshot`（同 id、同名字，旧内容归档）；`dedupeAccounts` 在每次刷新时处理历史遗留：同账号多卡时保留最新一张，其余目录重命名进 `kept/.history/<keptId>-<创建时间>` 后删除原卡，保证内容不丢；`renameSafely` 让安全快照不会把卡片名改成「切换前自动备份」。
- **root 命令超时**：`RootShell.exec` 用两个后台线程持续读 stdout/stderr，再对进程 `waitFor(90s)`；旧实现先阻塞读管道再判断超时，命令卡住时会永久挂起——表现为「点了没反应」，现已修复。
- **权限**：需要 `SYSTEM_ALERT_WINDOW`（悬浮窗）与通知权限；悬浮按钮由 `specialUse` 类型前台服务承载，服务未启动时 App 内的「悬浮按钮」按钮负责开启或关闭。悬浮按钮与主界面同一配色（圆角胶囊、强调色底、白字），拖动时会限制在屏幕范围内；通知标题会跟随当前分栏的游戏名更新。
- **按游戏隔离**：快照目录为 `files/snapshots/<包名>/<快照 id>/`，清单里记录 `package`，读取时校验归属，避免把星铁的清单当成分栏其他游戏的快照。旧版本把所有快照直接放在 `files/snapshots/` 下，启动时会一次性迁入对应包名目录。
- **未适配分栏**：原神（`com.miHoYo.Yuanshen`）与绝区零（`com.miHoYo.Nap`）只登记包名与入口，文件清单未调研，分栏内显示「尚未适配」，拍摄与切换按钮禁用。
- **启动游戏一律用命令**：App 内经 `am start -W -n <包名>/<入口>` 拉起；测试脚本同样只用命令行启动游戏，不模拟点击桌面图标，避免焦点不明时误触其他应用的图标。
- **快照加密**：payload 使用 Android Keystore 里的 AES-256-GCM 密钥（别名 `hoyoswitch-snapshot-v1`），存为 `<相对路径>.enc`，内容为 `HSN1` 魔数 + 12 字节 IV + 密文；清单只保存明文 SHA-256，不含密钥。旧版明文快照仍可读取，下一次更新时才写成加密格式。
- **历史版本**：更新快照前先把旧目录移入 `files/snapshots/<包名>/.history/<id>-<时间戳>`，最多保留最近 3 份；卡片菜单可回滚到任一归档版本，回滚前会把当前版本再归档一次。
- **构建**：沿用无 Gradle 流程，`python .\app\build.py` 调用 aapt2 → javac → d8 → zipalign → apksigner，产物 `app/build/account-switch.apk`，本地调试密钥 `app/build/local-test.p12`（均被 Git 忽略）。

## 4. 界面与主题

- 参考「轻控」的视觉：柔和深色底、白色（暗色下为深灰）大圆角卡片、无边框、编号小节标题、胶囊按钮。
- **固定暗色**：只保留 `values` 一套暗色调色板（不再保留 `values-night` 副本，避免两处配置漂移），主题为 `Theme.Material.NoActionBar`；强调色 `#7FA6FF`，主按钮文字用 `on_accent`（深色）保证对比度。
- 留白：页面左右各 24dp，卡片内边距 20dp、卡片间距 14dp，按钮之间 6–8dp；`targetSdk 36` 的边到边布局由 `OnApplyWindowInsetsListener` 把系统栏高度加回上下内边距，内容不会钻进状态栏。
- 头像使用 1650px 的应用图标，但按 `inSampleSize = 8` 采样成约 206px 再显示，避免一次解码约 11MB 的位图。
- 交互细节：胶囊按钮带 Ripple 反馈；禁用态按钮透明度 0.45；分栏文字单行省略、账号名最多两行省略；日志折叠时会连同「04 / 操作日志」小节一起隐藏；空态与「尚未适配」提示为 13sp 次要色、内边距使用 dp。
- 结构：头像＋应用名＋副标题＋版本胶囊 → 大标题「切号，轻一点。」→ 状态胶囊（圆点＋Root/游戏/当前账号）→ `01 / 游戏分栏` → `02 / 拍摄与切换` → `03 / 账号快照` → `04 / 操作日志`。
- 分栏为胶囊分段控件，选中项强调色填充；未适配的游戏整颗按钮半透明，选中后状态行与列表都会提示「尚未适配」。
- 账号卡片：当前登录项用强调色描边，标题加粗；主操作「切换到此账号」整行胶囊，次操作为「更新此快照」＋「⋯」。
- **一个账号一张卡**：按 `combo_widget` 里的账号标识归并；拍摄与切换都会原地更新当前账号已有的卡（旧内容进历史），不再每次新建卡；如果历史上同一账号存在多张卡，刷新时把较旧的合并进保留卡的历史并删除重复卡；加密密钥已失效、永远无法恢复的旧卡在创建满 10 分钟后自动移除。重命名后的名字在后续切换中会被保留（安全快照不会覆盖卡片名）。
- 日志为固定高度面板，可「隐藏日志／显示日志」，最多 200 行并自动滚到底。
- **弹窗统一风格**：不再使用系统 `AlertDialog`，改为自绘 `Dialog`——圆角 28dp 深色卡片、加粗标题、次要色说明、行项带 Ripple、底部胶囊按钮（取消为 tonal、确认为强调色）。账号卡片的「⋯」菜单做成带图标与说明的操作行：重命名（铅笔）、历史版本（时钟）、删除快照（垃圾桶＋红色标题与红色确认按钮）；历史版本列表复用同一行样式。行区最高 280dp、超出可滚动，避免条目多时把按钮挤出屏幕；宽度取「屏宽 − 48dp」与 520dp 的较小值，蒙层 55%。弹窗由 `visibleDialog` 统一管理，旋转或页面销毁时主动关闭，避免窗口泄漏。
- 竖屏单列：页头、大标题、状态胶囊、分栏、拍摄与切换、账号卡片、操作日志依次纵向滚动。
- **横屏两栏**：左侧为页头、状态胶囊、游戏分栏与拍摄/切换控件，右侧为账号卡片与日志，两栏各自独立滚动；横屏下隐藏大标题与副标题换取纵向空间，并把小节标题内边距收紧。旋转后通过 `onSaveInstanceState` 保留所选分栏、日志内容与日志折叠状态。

## 5. 真机验证（2026-11-19 14:18–15:10）

- App 内拍摄 A 快照 `20261119-142037`、B 快照 `20261119-142236`，均显示 10/10 文件存在。
- 在 App 里点 A 卡片的「切换到此账号」并确认：自动停止游戏、写入 4 个文件、自动保存安全快照 `20261119-142313`（切换前 B 状态）、启动游戏。
- 切换后账号库 1 行，`mid`/`aid` 与 A2 快照一致、与 B2 不一致；界面为「点击进入」＋「登出」；用户目视确认为账号 A。
- 失败路径（写入中途失败、回滚）代码已实现，但本轮没有制造故障去触发，属未验证项。
- 当前账号识别（14:32）：状态行显示「当前账号：20261119-142037」；点切换后对话框显示「当前账号：20261119-142037 / 目标账号：切换前自动备份」，取消后未写入任何文件。
- 识别依据只有 `combo_widget` 缓存，未与数据库行交叉校验；缓存缺失时会显示「已登录，但读不到账号标识」或「已登录，但不在任何快照中」。
- 卡片更新与悬浮按钮（14:39–14:43）：对不属于当前账号的卡片点「更新此快照」被拒绝，提示「当前登录的不是这个账号，未更新快照」；对当前账号卡片点击成功，`createdAt` 从 14:40:39 更新到 14:42:59 之后；开启悬浮按钮后，在 App 前台点悬浮按钮同样成功，日志记录「已用当前状态更新快照 20261119-142037」。
- 按游戏分栏（14:45–14:47）：三个分栏显示「原神（未适配）／星穹铁道／绝区零（未适配）」；切到原神分栏时状态行写「尚未适配」、列表提示不可拍摄切换、且不显示星铁的快照；切回星铁后原有 3 份快照仍在（旧目录已自动迁入 `com.miHoYo.hkrpg/`）。
- 加密与历史版本（14:49–14:51）：新拍快照 `20261119-144942` 的文件均以 `.enc` 保存，首 4 字节为 `HSN1`，界面显示 10/10；更新该快照成功（`createdAt` 从 14:49:42 变为 14:50:56），旧版本归档到 `.history/20261119-144942-1795071060220`。
- 回滚自检（14:53–14:54）：注入「写后校验失败」后，切换在写入第一个文件（令牌）后中止并自动回滚；日志 `SELFTEST PASS :: 自检：注入的校验失败；已回滚到切换前状态`。设备随后仍是 A：`login_status=true`、账号库与 A2 一致、与 B2 不一致。自检会留下两份「回滚自检基线」快照，属预期产物。
- 期间修复一处错误处理缺陷：成功回滚的提示原先写在 `try` 内，会被随后的 `catch (IOException)` 当成回滚失败，导致消息显示「回滚失败: 已回滚到切换前状态」；已改为在 try/catch 之外拼接结果。
- 卡片操作自检（14:59）：`CARDOPS PASS rename=true delete=true history_entries=1`——重命名后能读回新名称并复原；临时快照删除后不再出现在列表；历史版本计数与归档目录一致。
- 界面打磨（15:02–15:03）：明暗两套主题、卡片圆角描边、分栏选中态、日志折叠与行数上限；浅色与深色截图均正常。构建改为由 aapt2 生成 `R.java` 后编译（`app/build/gen`）。
- 审查—修复（15:04–15:11，共四轮，每轮修完即重建并复跑自检）：
  1. 取消切换对话框后 `busy` 未复位、悬浮按钮在未适配分栏仍可开启、更新快照先停游戏再校验账号、`su` 探测超时会抛 `IllegalThreadStateException`、写入标准输入可能因进程提前退出而抛错、切换产生的「切换前自动备份」无限堆积、`AccountUpdater.find` 死代码。
  2. 更新成功后重新启动失败会掩盖成功结果、悬浮服务静态标志可能过期。
  3. `refresh()` 并发返回可能覆盖新分栏 UI、拍摄时读取的 `game` 可能与实际不符、`logToggle` 字段重复声明、回滚历史时归档裁剪可能删掉待回滚版本。
  4. 悬浮按钮连点会并发执行更新、`SnapshotCrypto.random` 死代码。
- 最终自检：`CARDOPS PASS rename=true delete=true history_restore=true history_entries=1`、`SELFTEST PASS`。
- 说明：直接用 `input tap` 点对话框验证 UI 不可靠（曾点空导致重命名未生效），因此卡片逻辑改用 `--es selftest cardops` 这类命令式自检来验收；启动游戏也一律用 `am start`，不点桌面图标。

## 6. 已知限制

- 快照未加密：需求文档要求用 Android Keystore 加密存储，本原型直接写在 App 私有目录，属待实现项。
- 只适配星铁；原神、绝区零只是占位分栏，还没有文件清单，不能拍摄或切换。
- 只做拍摄与切换，没有重命名、删除、排序、搜索、回收站。
- UI 未做设计：无明暗主题、无空态插图、无非点按无障碍适配，日志区域固定占位。
- 只在已测设备与星铁 4.7.0 上验证；会话有效性前提与[删除账号后快照失效](../research/星铁登录状态点位与验证记录.md)第 10 节的结论一致。
- 包名、签名与正式发布证书均未确定。
- 悬浮窗权限需用户在系统设置里手动授予；重装后可能需要重新确认。
- 更新快照会覆盖该卡片旧内容，不保留上一版；只有切换前会自动生成「切换前自动备份」。
- 更新与悬浮按钮都直接读取当前状态，不会停止游戏；只有切换账号会先停止游戏并重新拉起，对局中切号会被中断。
- 历史版本只保留最近 3 份；回滚历史版本会先把当前版本归档，因此连续回滚仍可反悔一次。
- 启动游戏与测试一律用 `am start`，但卡片按钮的真机验收仍需点击；自动化点击必须先用 `mCurrentFocus` 确认前台是本 App，否则会误触桌面图标。
- 加密保护的是静态文件；设备已 Root 时，能运行 `su` 的程序仍可在运行时读取内存或应用私有目录，不能视为对抗同机高权限软件。
