# 账号切换 App

文档同步：2026-11-25。应用名「米游账号切换」，包名 `dev.hoyoswitch.app`，当前版本 **1.7.5**（versionCode 65）。此前已在星穹铁道 4.7.0、原神 7.2.0、绝区零 3.3.0 完成真机双向切换验证；1.7.0 验证了捐赠和关于页，没有重做账号切换测试。

> 本文以 1.7.4 为基准。历史实测保留当时的版本、时间和验证边界，本版未执行真机杀进程后的账号恢复复测。

## 1. 已实现

| 功能 | 说明 |
| --- | --- |
| Root 检测 | 依次探测 `su`、`/system/bin/su` 等候选路径，验证返回 `uid=0`；状态行只提示「未取得 Root」，具体失败原因在「更多工具 → 运行详情」 |
| 游戏识别 | 包名、版本（`dumpsys package`）与进程状态（`pidof`）；三款游戏共用，切换前要求游戏已停止 |
| 拍摄快照 | 每款游戏的固定清单均为 12 个条目，逐文件记录存在性、大小、SHA-256、属主、权限、SELinux 上下文；不存在的文件也记入清单，副本加密后存入 App 私有目录；游戏运行中也可拍摄 |
| 当前账号识别 | 星铁读 `login_status` + `combo_widget.account` 的 mid；原神/绝区零优先查询 `PORTE_ACCOUNT_PRODUCT.db`，查询失败时按时间戳降序扫描候选，并在设备识别和快照识别中分别与各自 token 键交叉确认。状态行显示快照名称，对应卡片标注「当前登录」 |
| 切换前确认 | 先读取当前账号；已是目标账号时直接提示且不停止游戏，否则弹出「当前账号 → 目标账号」确认框，确认后才停止游戏并执行切换 |
| 卡片更新快照 | 当前登录卡（以及无法读取的失效卡）主按钮为「更新快照」；其他卡片为「切换到此账号」。更新前校验当前登录账号，避免把别的账号覆盖进去 |
| 卡片菜单 | 每张卡片的「⋯」提供重命名、删除快照、历史版本；历史版本可回滚，回滚前先把当前版本归档 |
| 悬浮按钮 | 常驻悬浮的「更新快照」按钮（需悬浮窗权限），可拖动；用于切换并加载完成后，在游戏里直接刷新当前账号的快照 |
| 按游戏分栏 | 顶部三个分栏（原神／星穹铁道／绝区零），各自独立的快照列表与状态；快照按游戏包名分目录存放，不会混在一起 |
| 回滚自检 | 调试构建可用 `am start … --ez selftest true` 触发：注入一次写后校验失败，要求设备自动回到切换前状态并输出 PASS／FAIL |
| 卡片操作自检 | 调试构建可用 `--es selftest cardops` 触发：验证重命名、删除、历史版本计数并输出 `CARDOPS PASS/FAIL` |
| 账号卡片 | 每个账号一张卡（按账号标识去重），显示名称、更新时间与状态（快照无法读取 / 切换待验证）；文件数与上次使用时间在「⋯ → 快照详情」 |
| 账号密码区 | 每张卡提供「账号与密码」入口，弹窗内两行分别可复制、可编辑；密码用应用本地密钥（AES-256-GCM）加密后存进清单 |
| 切换账号 | 只写已验证的切换文件（星铁 4 个、原神 3 个、绝区零 3 个）；写前自动拍安全快照，逐文件读回校验，写入或校验报错时尝试回滚；自动停游戏并在成功后重新拉起 |
| 启动游戏 | 对当前分栏的游戏执行 `am start -W` |
| 分栏记忆 | 当前分栏写入 `SharedPreferences`，下次启动与自检命令都落在该分栏 |
| 签名与发布 | 调试签名与正式签名（RSA-4096）双模式；历次发布记录见第 8 节 |

## 2. 实现要点

- **命名空间**：已测设备的 per-app mount namespace 会隐藏其他包的数据，直接 `su -c cat /data/user/0/<游戏包>` 曾返回 `No such file or directory`。当前实现先探测 `nsenter`；可用时用 `nsenter -t 1 -m -- sh -c '<命令>'` 进入 init 的挂载命名空间，不可用时保留直接 `su` 路径，不将某一设备的条件推广到所有 ROM。
- **写入方式**：把字节写到 `su -c "cat > 目标文件"` 的标准输入。已有文件原位覆盖，通常保留 inode；必要时重建缺失文件，并复核或恢复属主、权限和 SELinux 上下文。
- **安全快照**：每次切换前先把当前状态原地写回当前账号已有的卡片（旧内容进历史）；只有该账号还没有卡片时才新建一张「切换前自动备份」。切换会**自动关闭游戏进程**：确认后先 `am force-stop` 并轮询 `pidof` 直到进程真正退出，再写入账号文件、校验、最后重新拉起游戏。任一文件校验失败就按这份安全快照回滚，并在界面日志里说明。若要切换的目标正是当前已登录账号，直接提示「当前已经是这个账号，无需切换」，不关游戏、不写文件。
- **切换文件**：星铁写 token prefs、SDK 偏好、`combo_widget.xml`、`PORTE_ACCOUNT_PRODUCT.db` 共 4 个主文件；原神、绝区零各为不含 `combo_widget.xml` 的 3 个。数据库切换还会处理关联边车；目标缺少 WAL/SHM 而设备存在时有拒绝保护。切换主文件的实测依据见各游戏点位记录，保护分支的实现不等于所有真机条件都已注入验证。
- **当前账号识别**：不使用文件哈希判断身份——客户端启动后会刷新令牌、SDK 偏好与数据库时间戳。星铁使用登录标志和组件缓存；原神、绝区零使用账号库候选与 token 键交叉确认。快照识别检查快照自身保存的 token，而非设备当前 token；界面只显示快照名称。
- **更新快照语义**：拍摄与更新都直接读取当前状态，**不需要停止游戏**；按当前账号匹配卡片后原地更新 12 条目清单及存在文件的副本，卡片名称与目录不变。不做自动更新——是否更新由用户手动决定。手动「拍摄快照」同理：账号已有卡片就原地更新，没有才新建。只有切换账号会先停止游戏。
- **运行中拍摄的一致性**：非数据库条目由 5 个工作线程读取，运行中的必要切换文件采用稳定重读；每个数据库与清单内的边车分组读取，运行时要求连续两组结果一致（最多 3 轮、间隔 100ms）。分组协议记录存在性和字节长度，空文件与缺失文件分开处理，`stat`/`cat` 失败会中止。`forceStop()` 后轮询 `pidof`（最多 4 秒）确认进程退出。历史拍摄耗时见实测记录，不作为当前版本的统一性能承诺。
- **只保留一张卡的实现**：`captureAccount` / `snapshotCurrentAccount` 按账号标识找现有卡，命中就更新原卡，旧内容归档；`dedupeAccounts` 归并历史重复卡及其旧历史。`renameSafely` 避免安全快照把卡片名改成「切换前自动备份」。
- **root 命令超时**：`RootShell.exec` 用两个后台线程持续读 stdout/stderr，再对进程 `waitFor(90s)`；旧实现先阻塞读管道再判断超时，命令卡住时会永久挂起——表现为「点了没反应」，现已修复。
- **权限**：需要 `SYSTEM_ALERT_WINDOW`（悬浮窗）与通知权限；悬浮按钮由 `specialUse` 类型前台服务承载，App 内按钮负责开启或关闭。悬浮按钮可拖动并限制在屏幕范围内；服务绑定的游戏单独写入偏好键 `floating_enabled_game`（文件 `ui.xml`），不随主界面切换分栏改变，系统重建服务时恢复该绑定。
- **按游戏隔离**：快照目录为 `files/snapshots/<包名>/<快照 id>/`，清单里记录 `package`，读取时校验归属，避免把星铁的清单当成分栏其他游戏的快照。旧版本把所有快照直接放在 `files/snapshots/` 下，启动时会一次性迁入对应包名目录。
- **已适配的游戏**：星铁（4 个切换主文件）、原神 7.2（3 个）、绝区零 3.3（3 个），账号文件与验证过程见各游戏点位记录。星铁使用登录标志与 `combo_widget.xml` 的 `account.mid`；原神与绝区零优先查询账号库，回退时遍历按时间戳降序排列的候选，并用各自 token 键确认，不直接取 token 文件的第一个 key。
- **启动游戏一律用命令**：App 内经 `am start -W -n <包名>/<入口>` 拉起；测试脚本同样只用命令行启动游戏，不模拟点击桌面图标，避免焦点不明时误触其他应用的图标。
- **快照加密**：payload 使用 Android Keystore 里的 AES-256-GCM 密钥（别名 `hoyoswitch-snapshot-v1`），存为 `<相对路径>.enc`，内容为 `HSN1` 魔数 + 12 字节 IV + 密文；清单只保存明文 SHA-256，不含密钥。旧版明文快照仍可读取，下一次更新时才写成加密格式。密钥只在别名确实不存在时才生成，取不到时直接报错，不会静默重建密钥导致旧快照全部失效。无法解密的卡片会标红显示「快照无法读取」，**绝不自动删除**，只能由用户手动删除；此时主按钮改为可点击的「更新快照」，可用当前登录状态覆盖该卡（程序无法校验它原本对应哪个账号，需用户在确认框里自行确认）。
- **历史版本**：更新快照前先把旧目录移入 `files/snapshots/<包名>/.history/<id>-<时间戳>`。历史裁剪按卡分开，每张卡最多保留 3 份；列表和裁剪共用归档时间排序。卡片菜单可回滚到任一归档版本，回滚前会把当前版本再归档一次，回滚后保留卡片当前的 id 与名称，只把内容与时间换成历史版本。
- **账号密码与 SDK 上限**：账号密码只作备注用途（不影响切换），密码以应用本地密钥（AES-256-GCM，密钥文件 `files/password-notes.key`，与清单同处应用私有目录）加密后存进清单；`lastUsedAt` 在每次切换成功时刷新。凭据密钥不经过 Keystore：能完整复制应用 `files/` 目录（root 或取证备份）即可同时获得密钥与密文并解出密码，它只防随手查看，不防已取得数据目录的攻击者。SDK 本身允许 **50 个账号**（默认 10，游戏自定义模块改成 50），超出时按 `timestamp` 淘汰最旧的一条，证据见[原神点位记录 §6](../research/原神账号状态点位与验证记录.md)。
- **构建**：沿用无 Gradle 流程，`python .\app\build.py` 调用 aapt2 → javac → d8 → zipalign → apksigner。中间文件放在临时目录并在结束时删除；正式包还会比对固定证书指纹，只有通过校验的 APK 才会替换仓库根目录 `dist/` 中的对应产物（均被 Git 忽略）。
- **签名与发布**：
  - 调试构建：`python .\app\build.py`，用 `app/build/local-test.p12`（CN=Local Prototype）签名，产物 `dist/account-switch.apk`。
  - 正式构建：`python .\app\build.py --release`，需提前准备原有的 `app/keystore/hoyoswitch-release.p12` 和同目录的 `keystore.txt`。缺少任一文件时构建终止，不生成替代密钥。仅当 APK 的唯一签名证书与预设 SHA-256 `81a5fc64529c23f1eef5a9de9cf32d6f6d71684aaf655c33f0adae36f59f9079` 一致时，才会替换 `dist/account-switch-release.apk`。
  - 密钥与口令位于 `app/keystore/`（已由 Git 忽略）；请单独安全备份这两份文件。源码仓库不是签名密钥的备份。
  - **同签名正式版升级**：包名和签名一致、版本号允许升级时，使用 `adb install -r <APK路径>`，不需要卸载，也不会因覆盖安装而清除已有快照。**调试版与正式版互换**等签名不同时，才需要卸载后换装；卸载会删除 App 数据与快照加密密钥，已有快照需要重新拍摄。
  - **密码备注迁移**：旧版备注若仍可读取，在编辑页保存一次即可改用应用本地密钥。若旧备注已经读不出来，新版本不会恢复旧密文；取消或留空不会覆盖原记录，只有主动选择「重新录入」并保存非空密码才会替换。若要清除仍可读取的密码，清空输入框后点击保存，勾选「确认清除已保存的密码备注」再保存。卸载或清除应用数据会同时删除密码备注与本地密钥，应用内加密不等同于密码备份。

### 历史整理与中断恢复（1.6.4）

以下行为自 **1.6.4** 起提供，未包含在 `v1.6.3`。已通过离线测试，但未在真机执行杀进程复测；详见[发布与待发布状态](../PROGRESS.md#发布与待发布状态)。

- **历史合并和裁剪**：先迁移重复卡的历史，再归档旧卡，全部成功后才裁剪；失败时保留旧卡和未迁移的历史，便于重试。列表和裁剪用同一套归档时间排序。同一时间戳重名只追加 `.序号`，不改变归档时间。
- **更新或历史回滚中断**：交换目录前先写记录。下次扫描时，未完成替换就恢复原卡，替换已完成就补齐清单和历史裁剪。只处理有交换记录的操作，不自动搬动旧版遗留的孤立归档。
- **账号切换中断**：首次写入游戏文件前记录切换前的安全快照。若 App 被终止，再次打开对应游戏分栏并刷新时会尝试恢复。游戏仍在运行或进程状态未知时不写入、不删除备份。待恢复时不要从桌面启动游戏；先停止游戏，再回到 App 刷新。

## 4. 界面与主题

### 1.6.5 界面优化

- 竖屏按游戏分栏、当前账号和快捷操作、账号列表排列；压缩页首，把命名输入移到拍摄对话框。横屏保留左侧操作、右侧快照两栏。
- 当前账号卡片突出「更新快照」，其他可切换账号突出「切换到此账号」。每张卡保留直接的「账号与密码」入口，可查看、复制或编辑备注，密码默认遮盖。文件计数在「⋯ → 快照详情」；历史、重命名和固定排序调整也在卡片菜单。
- 同一游戏有多张快照时，长按卡片右上角的「↕」，拖到目标卡片的上方或下方后松开。拖到列表边缘会自动滚动。实际换位后切到「固定顺序」，新顺序按游戏保存；「⋯」中的上移和下移仍可使用。
- 正常状态优先显示当前账号和游戏进程状态，Root 与游戏版本放在「更多工具 → 运行详情」。恢复待处理时提供重试入口；顶部版本号标注为 `App x.y.z`。操作日志默认折叠，可从「更多工具」展开。

### 主题（1.6.6）

从首页「更多工具 → 主题」选择「跟随系统」「暗色模式」或「亮色模式」。默认跟随系统，手动选择会保存且不再随系统外观变化，直到切回「跟随系统」。配色覆盖主界面、弹窗、系统栏图标和悬浮按钮；切换主题不会重绑悬浮按钮的游戏或改变它的位置。正在操作快照时，请等操作完成后再换主题。

### 捐赠和关于

「更多工具 → 捐赠」加粗标明工具免费、捐赠自愿且不影响功能，并展示原始微信赞赏码和支付宝二维码。「更多工具 → 关于」先显示与 README 一致的知识产权声明，加粗个人独立原创及责任边界，再显示项目地址和操作说明。

- 结构：头像＋应用名＋副标题＋版本胶囊 → 大标题「切号，轻一点。」→ 状态胶囊（圆点＋Root/游戏/当前账号）→ `01 / 游戏分栏` → `02 / 拍摄与切换` → `03 / 账号快照` → `04 / 操作日志`。
- 分栏为胶囊分段控件，选中项强调色填充；未适配的游戏整颗按钮半透明，选中后状态行与列表都会提示「尚未适配」。
- 账号卡片：当前登录项用强调色描边，标题加粗；主操作「切换到此账号」整行胶囊，次操作为「更新此快照」＋「⋯」。
- **账号密码区**：卡片内嵌一块淡色面板，两行分别是「账号：xxx」与「密码：••••••••」，每行右侧各有一个「复制」按钮，**账号与密码分别复制、互不影响**；点「编辑账号密码」弹出双输入框，密码默认打码，点右侧眼睛图标切换显示/隐藏，保存后写入清单。密码用本地密钥（AES-256-GCM）加密后以 `passwordEnc` 存进 `manifest.json`，明文密码不会落盘；账号名按原文保存。
- 卡片元信息显示「快照时间 · 文件数 · 上次使用」，切换成功时更新 `lastUsedAt`；当同一游戏保存到 45 个以上账号时，列表顶部出现红色提示，说明游戏 SDK 上限为 50、登录新账号可能淘汰最久未使用的账号。

- 日志为固定高度面板，可「隐藏日志／显示日志」，最多 200 行并自动滚到底。
- **弹窗统一风格**：不再使用系统 `AlertDialog`，改为自绘 `Dialog`——圆角 28dp 深色卡片、加粗标题、次要色说明、行项带 Ripple、底部胶囊按钮（取消为 tonal、确认为强调色）。账号卡片的「⋯」菜单做成带图标与说明的操作行：重命名（铅笔）、历史版本（时钟）、删除快照（垃圾桶＋红色标题与红色确认按钮）；历史版本列表复用同一行样式。行区最高 280dp、超出可滚动，避免条目多时把按钮挤出屏幕；宽度取「屏宽 − 48dp」与 520dp 的较小值，蒙层 55%。弹窗由 `visibleDialog` 统一管理，旋转或页面销毁时主动关闭，避免窗口泄漏。

## 6. 已知限制

- **会话有效期前提**：快照只在登录会话有效期内可切换；在游戏内删除账号或清除数据会让旧快照永久失效（实测），需要重新登录并重拍。
- **只在已测版本验证**：星铁 4.7.0、原神 7.2.0、绝区零 3.3.0；大版本更新后文件清单可能变化，是否启动差分与兼容性回归按第 7 节的按需安排决定，现有结论不自动扩展到新版本。
- **切号会中断对局**：切换前必须停止游戏，写文件并校验后才重新拉起。
- **无回收站**：删除卡片不可恢复；历史版本只保留最近 3 份/卡。
- **SDK 上限 50 个账号/游戏**：超出时游戏会淘汰最久未使用的账号；App 在 ≥45 个时提示，但不阻止。
- **签名迁移代价**：正式版与调试版签名不同，互换时需卸载，届时 App 数据和快照密钥会被删除。同签名正式版正常升级不需要卸载。
- **加密边界**：只保护静态文件；设备已 Root，同机高权限程序仍可在运行时读取私有目录，不能视为对抗 Root。
- **悬浮窗权限**需手动授予；重装后可能需要重新确认。
- **自动化点击**需先用 `mCurrentFocus` 确认前台是本 App，否则会误触桌面图标；启动游戏一律用 `am start`。
- **账号密码仅为备注**，不参与切换；密码以应用本地密钥（AES-256-GCM）加密后写入清单，卡片与列表只显示掩码。
