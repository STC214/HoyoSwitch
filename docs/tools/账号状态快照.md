# 星铁账号状态快照与恢复

更新：2026-11-19。PC 端验证工具，用于切换前保存、切换后恢复账号相关文件；不是交付 App 的功能。

## 1. 覆盖的文件

路径均相对于 `/data/user/0/com.miHoYo.hkrpg/`。

| 文件 | 作用 |
| --- | --- |
| `shared_prefs/porte_sdk_account_PRODUCT.xml` | Porte 生产环境登录状态（`login_status`） |
| `shared_prefs/porte_sdk_token_PRODUCT.xml` | Porte 令牌存储 |

| `shared_prefs/mdk_passport_sp.xml` | 通行证偏好 |
| `databases/PORTE_ACCOUNT_PRODUCT.db`（含 `-journal`／`-wal`／`-shm`） | 已保存账号表 |
| `databases/mihoyo_account`（含 `-journal`／`-wal`／`-shm`） | 旧账号库 |

### 1.1 明确不参与切换的文件

以下内容即使存在于设备，也不纳入切换快照，理由是设备绑定或与账号无关；误换它们可能触发反外挂或设备校验：

| `app_webview/`、`app_telemetry/` | WebView 数据与遥测队列 | 非账号状态，且体积大、变化快 |
| `cache/`、`no_backup/` | 缓存与 `androidx.work` 工作库 | 可重建或与账号无关 |
| `/data/user_de/0/com.miHoYo.hkrpg/shared_prefs/` | `move_to_de_records.xml`（`push_client_self_info=true`）、`push_client_self_info.xml`（`push_kit_auto_init_enabled=false`） | 2026-11-19 只读核对：两个键均为推送开关，与账号无关 |

## 2. 一致性前提

- 游戏必须停止：采集与恢复在检测到进程时直接拒绝。
- 采集时每个文件读两次比对摘要，避免读到正在写入的内容。
- 采集只读设备，不修改任何文件。

## 3. 命令

```powershell
python .\tools\starrail\snapshot.py --serial <序列号> capture
python .\tools\starrail\snapshot.py --serial <序列号> verify --record <快照目录> --remote
python .\tools\starrail\snapshot.py --serial <序列号> diff --record <快照目录>
python .\tools\starrail\snapshot.py --serial <序列号> restore --record <快照目录>
python .\tools\starrail\snapshot.py --serial <序列号> restore --record <快照目录> --apply
```

- `capture`：新建快照目录，保存文件副本与 `manifest.json`（大小、SHA-256、属主、权限、SELinux 上下文、mtime）。
- `verify`：校验本地副本与清单；加 `--remote` 时同时与设备比对。
- `diff`：只读比对设备与快照，列出 `same`／`different`／`missing`／`metadata-differs`／`gone`／`extra`。
- `restore`：默认 dry-run，`--apply` 才写入。

## 4. 恢复语义

- 写入前自动生成「恢复前安全快照」，恢复失败或不理想时可用它回退。
- 只写内容不一致的文件，内容一致的文件跳过。
- 通过 `cat > 目标文件` 覆盖，保留 inode，属主／权限／SELinux 上下文不变。
- 设备上已不存在的文件会重新创建，随后补 `chown`／`chmod`／`chcon`，再校验。
- 快照里没有、设备上多出来的文件不删除，只报 `extra`。
- 恢复后逐文件读回，比对字节与属主／权限／上下文；全部一致才返回 0。

## 5. 已验证结果

2026-11-19 13:19–13:20，星铁 4.7.0（版本代码 122），Android 主用户 0，KernelSU。

| 步骤 | 结果 |
| --- | --- |
| 采集 | 14 个目标中 10 个存在并保存，4 个 `-wal`／`-shm` 不存在 |
| `verify --remote` | 通过（本地副本与设备一致） |
| `diff` | 14 项全部 `same`／`gone`，退出码 0 |
| 制造差异 | 用[登录状态开关](登录状态开关.md)把 `login_status` 改为 `true`，`diff` 报 1 处 `different` |
| `restore --apply` | 写入 1 个、跳过 9 个，自动安全快照，最终 14 项一致，退出码 0 |
| 最终设备状态 | `login_status=false`，`a089179d…`，与实验前一致 |

### 5.1 第一次真实切换验证：B → A（2026-11-19 13:29–13:34）

条件：同一台设备与版本；A 于 13:29 登录并拍快照 `20261119-133030`，B 于 13:32 登录并拍快照 `20261119-133352`。

| 步骤 | 结果 |
| --- | --- |
| A、B 快照差异 | 4 个文件：`porte_sdk_token_PRODUCT.xml`（433→816 B）、`mihoyo_sdk_preference.xml`、`combo_widget.xml`（2071→2085 B）、`PORTE_ACCOUNT_PRODUCT.db` |
| 恢复 A 快照 | 写入 4 个、跳过 6 个，自动保存 B 的安全快照 `20261119-133414`，最终 14 项一致 |
| 冷启动后界面 | 「点击进入」＋「登出」，即已登录态，未出现重新登录或验证提示 |
| 冷启动后数据库 | 1 行，`mid`／`aid` 与 A 快照一致；`timestamp` 更新为 13:34:45，说明客户端接受了该状态并刷新 |
| 冷启动后组件缓存 | `combo_widget` 的 `account` 与 A 快照一致，B 的两行记录消失 |
| 用户确认 | 目视确认为账号 A |

本次只证明「恢复这 10 个文件」在当前条件下能让客户端以 A 登录，不证明它是最小集合：实际变化的是上述 4 个文件，其余 6 个未变但仍属于候选集。

## 6. 存储与敏感数据

- 快照位于被 Git 忽略的 `account-snapshots/state/<时间>/`，含令牌与加密账号数据。
- 按敏感数据处理：不上传、不复制进公共文档目录。`login-state` 与 `state` 两类目录都属本机材料。

## 7. 与「备份工具箱」整包备份的关系

对照对象：`/storage/emulated/0/Download/backup0/AppBackup/com.miHoYo.hkrpg/` 下 2026-11-18 的两份备份（23:28、23:47），结论来自归档实物与工具箱 APK 字符串。

- 工具箱做法：备份前 `am force-stop` 目标应用；root 下用自带 tar + zstd 打包 `/data/user/0/<包名>`（相对路径，保留 uid／gid／mode），再单独打包 `/data/user_de/0/<包名>`；归档排除 `cache/` 与 `no_backup/`。元数据只有 `!BackupInfo!<包名>.json`（包名、应用名、版本、两个时间戳）。
- 实测每份归档 140 个文件：`shared_prefs` 37、`databases` 22（含 `-journal`／`-wal`／`-shm`）、`files` 33、`app_webview` 37、`app_telemetry` 11。
- 覆盖关系：上表 10 个候选文件全部在内，工具箱备份是超集，文件层面不缺。
- 但不适合直接拿来做切换：
  1. 无逐文件清单与哈希，归档损坏或截断无法发现；
  2. 归档无 SELinux 标签（xattr 为 0），恢复只能 `restorecon -RF` 事后重标，MCS 类别能否精确还原未验证；
  3. 整包粒度，恢复会连带 WebView、遥测与 `files/`，并抹掉备份之后新增的账号与登录态；
  4. 没有恢复前落点，也没有版本／渠道校验；对游戏数据的恢复路径本身未实测。
- 定位：工具箱备份做整包保险，切换只用本工具列出的最小集合。

## 8. 限制

- 只覆盖上表候选文件；组合服、其他渠道服、原神与绝区零均未验证。
- 切换只验证了一次 B → A（13:29–13:34），且 A 的令牌是数分钟前刚获得的有效会话；未验证：
  - 反向 A → B；
  - 令牌放置较久后是否仍能恢复登录；
  - 进入角色、切换后长时间在线，以及服务端风控或验证介入的场景；
  - 客户端在恢复后的首次启动会重写令牌与数据库 `timestamp`，这属于正常刷新，不能据此判断账号身份。
- 是否是「最小可切换集合」未验证：本次实际发生变化的是 4 个文件，其余 6 个未变但仍在候选集内。
- 未验证恢复中途断电或中断的情形；遇到时用自动生成的安全快照回退。
- 未验证游戏运行中的并发写入场景；工具在检测到进程时直接拒绝执行。
