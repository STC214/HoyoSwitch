# 星铁登录状态开关（PC 端验证工具）

更新：2026-11-19。本工具是 PC 侧的可逆验证脚本，不是交付的安卓 App。

> 状态：App 1.0.0 已完成账号切换实现，本工具保留用于验证 `login_status` 行为与排障。

## 1. 用途与边界

- 只读写 `/data/user/0/com.miHoYo.hkrpg/shared_prefs/porte_sdk_account_PRODUCT.xml` 中的 `login_status`。
- `shared_prefs/mihoyo_sdk_preference.xml` 的同名字段只做只读展示：实测中它不随登录／登出变化，写入它没有意义。
- 不修改数据库、令牌文件、组件缓存，不重放登录或验证请求，不输出账号标识与凭据。多文件备份与恢复见[账号状态快照](账号状态快照.md)。
- 该布尔值只表示本地 Porte SDK 是否允许返回已保存账号，不是服务端认证结果。

## 2. 前提

- 手机已连接 ADB，且 `su` 可用（本机实测为 KernelSU）。
- 目标游戏进程必须停止；工具检测到进程时会拒绝写入。
- 执行 `su` 后首次授权可能需要在手机上确认。

## 3. 用法

```powershell
python .\tools\starrail\login_state.py --serial <序列号> status
python .\tools\starrail\login_state.py --serial <序列号> set --value true
python .\tools\starrail\login_state.py --serial <序列号> set --value true --apply
python .\tools\starrail\login_state.py --serial <序列号> restore --record <备份目录> --apply
```

- `status`：只读。输出布尔值、SHA-256 前缀、大小、修改时间、属主、权限与 SELinux 上下文。
- `set`：默认 dry-run，只打印计划与前后摘要；加 `--apply` 才写入。
- `restore`：用备份目录中的 `original.xml` 还原，同样默认 dry-run。
- 退出码 0 表示已校验成功；非 0 表示未写入、被拒绝或已还原。

## 4. 安全设计

- 写前检查游戏进程，运行中直接拒绝。
- 逐字节备份到 `account-snapshots/login-state/<时间>-<旧值>-to-<新值>/`，含 `original.xml` 与 `meta.json`（含还原命令）。
- 通过 `cat > 目标文件` 覆盖写入，保留 inode，因此属主、权限与 SELinux 上下文不变。
- 写后重新读取整份文件，比对字节、布尔值，以及属主／权限／上下文；任一项不符立即用备份还原并退出非 0。
- 只替换 `login_status` 一处；文件里 0 个或多个同名 `boolean` 项时拒绝执行。
- 文件大小与修改时间本来就会变，不作为失败条件。

## 5. 已验证结果

2026-11-19 13:13–13:14，星铁 4.7.0（版本代码 122），Android 主用户 0，KernelSU。

| 步骤 | 读数 |
| --- | --- |
| 写入前 | `false`，120 字节，`a089179d…`，界面为手机号登录页 |
| 写入 `true` | 119 字节，`ee1d6073…`，属主 10300:10300、660、上下文均未变，读回一致 |
| 冷启动 14 秒后 | 仍为 `true`，客户端未改写；界面仍是手机号注册／登录 + 短信验证码 + 「进入游戏」 |
| 还原 | `false`，120 字节，`a089179d…`，属主／权限／上下文复核一致 |

结论：在当前账号数据状态下，仅翻转这个布尔值不足以恢复已登录界面；这只否定「单改此值即可登录」这一种假设，不否认证件有效且存在已保存账号时它是必要条件。

副作用：该偏好文件的修改时间由 11:49:31 变为 13:14:42，此前以 11:49:31 为基线的文件时间对比不再适用；布尔值语义未变。

## 7. 限制

- 只在上述设备与星铁版本验证；其他版本、渠道服与其他两款游戏未验证。
- 未验证「存在有效会话与已保存账号」时翻转 `true` 的行为，也未验证数据库或令牌层面的切换。
- 备份保存在被 Git 忽略的 `account-snapshots/`，含原始偏好文件，按敏感数据处理。
